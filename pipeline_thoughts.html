Full Vision vs. CA3 Scope

Teacher's Pet is the scoped CA3 instance of a generalisable model: a personal knowledge concierge that indexes a professional's private library against their domain's reference frameworks and fills gaps intelligently.

Reference Taxonomies — Tying Resources to Outcomes

Resources get tagged not just by what they are but by what curriculum outcome they serve. This unlocks the two capabilities the brief requires: outcome-to-resource mapping, and gap detection.

Two regimes, one system

RegimeSubjectsOutcome formatCA3 scope
New framework (with codes) Primary Language (2019), Primary Maths (2023) TF codes (Language), Progression Continua PC1–PC12 (Maths) Full outcome mapping
1999 curriculum (prose only) SESE, SPHE, PE, Arts No outcome codes. Strand/unit prose per class band. Skeleton only (synthetic strand/stage codes, no outcome matching)

Gap detection engine

Iterate all curriculum outcomes → query catalogue for each → any outcome with zero resources above confidence threshold is a gap → triggers Ops-Researcher to search curriculumonline.ie → if found, suggest to teacher → if not and teacher requests: Ops-Maker generates lesson plan. This is the core agent handoff chain that maps to 25% of the grade.

Nine Numbered Decisions

Decision 1: Deep-parse all in-scope PDFs

Full deep parse of all ~3,300 PDFs is trivially cheap (~$6–16, ~90 min). There is no meaningful time or money saving from sampling. The catalogue is the product; it deserves honest tagging. Text-rich files → pdfplumber + DeepSeek classification. Image-heavy files → Gemini Flash vision (1 page per file for subject/format/grade; text extraction covers the rest).

→ Decision: Parse all PDFs in-scope. ~$6–16, ~90 minutes. Run overnight for image-heavy batch.

Decision 2: English + Maths only. Trim catalogue to match.

Language + Maths covers both Irish curriculum taxonomy styles (coded TF outcomes vs. progression continua). Adding more subjects is rote transcription. Trim catalogue to files whose primary subject is English or Maths (~1,800–2,200 files). Cross-curricular seasonal folders (xmas, halloween, back-to-school) stay in if content is literacy/numeracy.

→ Decision: Reference taxonomies for Primary Language (TF codes) + Primary Maths (PC continua). Catalogue trimmed to ~1,800–2,200 English/Maths files.

Decision 3: No Gaeilge

LLMs are materially weaker in Irish. Generating Irish-language educational content is an active research problem, not a CA3 deliverable. ~119 Gaeilge files tagged from folder only, excluded from demo queries. Named as deliberate exclusion with specific reasoning in the writeup — demonstrates AI-limitation awareness.

→ Decision: Exclude Gaeilge from catalogue, parsing, generation, and demo.

Decision 4: UFLI programme reference

UFLI Foundations (University of Florida Literacy Institute) is a structured phonics programme with 128 lessons in a fixed scope-and-sequence: Lesson 1 starts with short 'a' CVC words, through to affixes and advanced word study by Lesson 128. 24 files in the collection are already UFLI-tagged by filename. Authoring the scope-and-sequence as JSON lets the system answer "UFLI Lesson 54" queries, cross-reference to curriculum outcomes, and prevent generated plans from using untaught sounds. This is a separate reference layer from curriculum outcomes — a resource can be tagged with both.

→ Decision: Author full 128-lesson UFLI scope-and-sequence as JSON. Numicon and morphology taxonomies as skeletons only.

Decision 5: Search first, generate as fallback

Gap resolution: (1) query catalogue → (2) if gap, search curriculumonline.ie for public NCCA resources → (3) teacher reviews suggested resources, adds to catalogue → (4) only if nothing found and teacher requests: Maker generates a lesson plan. Generated content is marked with AI provenance. Teacher keeps control of what enters their catalogue.

→ Decision: Search-first, generate-as-fallback. Bundle = matched resources + teacher-approved discovered resources + generated lesson plan (only if gaps remain). No worksheet generation.

Decision 6: App-only Graph auth for demo, MSAL.js delegated auth for bundle downloads

The Worker uses Azure AD app-only credentials (client credentials flow) for audit logging and catalogue reads. For bundle file downloads from OneDrive, a separate MSAL.js delegated auth flow was implemented: the user signs in via popup with Files.Read scope, and the delegated token is passed to the Worker which uses /me/drive/root: to fetch files from the user's personal OneDrive. The auth dialog offers two paths: "Sign in with Microsoft" (includes actual resource files in the zip) or "Continue without files" (zip with README + generated plans only). This solves the documented personal OneDrive app-only auth limitation (Decision 7).

→ Decision: Ship with app-only auth for server operations. Add MSAL.js delegated flow for bundle file downloads. Popup-based, no redirect/profile-hopping.

Decision 7: Switch catalogue from OneDrive XLSX to GitHub Pages JSON

Personal OneDrive (hotmail.com) does not support Microsoft Graph app-only (client credentials) authentication — the Worker's calls to /drive/root:/Teaching Resources/Catalogue.xlsx:/workbook/tables/ returned 401. The catalogue is the pipeline's sensor — without it, the Researcher has nothing to search. The solution: serve the catalogue as a static JSON file from the same GitHub Pages repo that hosts the frontend. The Worker fetches data/catalogue.json on cold-start and caches it in memory. The catalogue_populator.py writes directly to data/catalogue.json instead of outputting XLSX for OneDrive upload.

→ Decision: Catalogue served as static JSON from GitHub Pages. Worker fetches at cold-start. Catalogue_populator.py writes JSON directly. OneDrive Excel path retained for audit logging only (still works for app-only auth — the table rows endpoint is separate from file access).

Consequence: Bundle file downloads from OneDrive still use app-only auth and fail for personal accounts. This is a known limitation — the bundle zip contains README + generated plans but no actual resource files. Documented in README Limitations, QA page O01, and this decision.

Decision 8: Split Keelin into Dev-Keelin + Ops-Keelin

The original design had a single Keelin agent. During Claude-assisted review, it became clear that security review (what guards the deployment boundary) and content QA (what guards the teacher boundary) are fundamentally different domains. Dev-Keelin audits secrets, CORS, Graph scopes, and wrangler.toml — blocking deployment on failure. Ops-Keelin validates generated lesson plans for hallucinations, UFLI boundary violations, and paired-prompt bias — blocking content from reaching the teacher on failure. Their scopes don't overlap: failing one doesn't mean failing the other. This split reflects the module's trust calibration argument (Lee & See 2004): different trust dimensions need different guards.

→ Decision: Two Keelins with non-overlapping scopes. Dev-Keelin in agents/dev/, Ops-Keelin in agents/ops/. Both block on fail: Dev-Keelin blocks deployment, Ops-Keelin blocks content delivery.

Decision 9: Warm visual identity via Claude-assisted design

The initial frontend was functional but stark — white background, standard fonts, minimal styling. The module's UX frameworks (CASA, Fogg B=MAP, Cialdini's liking principle) implied a visual identity should match the system's role: a trusted colleague, not a clinical tool. Claude (via OpenCode) was prompted for a warm, library-inspired theme appropriate for a teacher-facing concierge system. Output: Fraunces (serif display) + Public Sans (body) + IBM Plex Mono (badges/confidence scores), cream background (#f2ecd9) with dot-grid texture, library card-catalogue styling for resource cards (top accent bar, double-rule shadow, stacked hover effect), painted-card tab design with polygon clip-paths, and a four-colour semantic badge system (accent green, success, warning/amber, purple for AI-generated). The dot-grid background and warm palette deliberately evoke a teacher's physical resource library.

→ Decision: Apply warm library-card visual identity across all pages (frontend, pipeline_thoughts, QA dashboard). Design rationale documented in the CASA and Cialdini framework assessments in the QA page.

CA3 scope— what's deliberately excluded

Per the module's Project Brief and grading criteria, the following are explicitly out of CA3 scope:

FeatureReason for exclusion
Collaborative filteringSingle-teacher prototype. No multi-user ratings, no co-purchase data, no user-user similarity. Content-based recommendation only (catalogue search + semantic scoring).
Reinforcement learningAgents are specified via BDI (Rao & Georgeff 1995), not trained via RL (Sutton & Barto 2018). Module explicitly treats RL as a "glance" only — the module's agents use BDI specification.
Persistent state / user accountsNo login, no localStorage persistence, no session history. All state is in-memory. The bundle sign-in (MSAL.js) is only for OneDrive file access — not for account management.
Like / Dislike / Review ratingsNo thumbs-up/down, no review flags, no feedback loop into the catalogue. The UX is transactional: search → select → bundle download.
Gaeilge generationLLMs unreliable in Irish. Catalogue resources matched and returned but no AI-generated Irish-language content (Decision 3).
Worksheet/slide/printable generationMaker produces markdown prose only — lesson plan descriptions. No PDFs, worksheets, images, or printable content (Decision 5).

Design Journey Log — how we got here

Phase 1: Folder-Level Categorisation

First pass treated the teacher's own folder structure as the taxonomy. Result: 3–4 tags per file in 30 seconds. But missed format, grade band, pedagogy, source, licensing, and cross-cutting resources (a Christmas phonics worksheet in xmas/ not phonics/).

Phase 2: Content-Level Experiment

Tested 3 PDFs in fall resources literacy numeracy. Content extraction tripled tags (3 → 6–8 per file). Discovered two were identical duplicates. But 9 of 14 pages in one file yielded zero extractable text — the hard ceiling: image-heavy worksheets.

Phase 3: Quantifying Approaches

Benchmarked on 50 random PDFs. Full deep parse: ~90 min, ~$5 API. Optimised (gaps only): ~10–15 min, ~$0.55. 30% of PDFs image-heavy (<500 chars), 48% text-rich (>2,000 chars). The cost argument for sampling collapsed — $5 is trivially cheap.

Phase 4: Image-Heavy PDF Problem

Explored four solutions: Tesseract OCR (free, 14+ hours), Azure Document Intelligence (~$37), Marker (free, GPU-recommended, 14+ hours), Vision LLMs (Gemini Flash ~$2–12.50, captures pedagogical intent directly from the visual layout). Vision LLMs won on cost, speed, and quality of tag inference.

Phase 5: Reference Taxonomies

Discovered two-regime problem: modernised curriculum has outcome codes (TF, PC); 1999 curriculum doesn't. No public API from NCCA — taxonomies must be hand-authored. Jolly Phonics absent from collection despite being Ireland's dominant programme; UFLI is the teacher's chosen method (24 files).

Phase 6: Gap Filling Strategy

Evolved from "generate for every gap" → "search first, generate as fallback." Teacher keeps control of what enters their catalogue. curriculumonline.ie scraping tested and confirmed viable (91 outcome prose matches in raw HTML).

Phase 7: Architecture Decisions

Google Sheets → Excel Online (MS ecosystem). Client-side JSZip → Cloudflare Worker server-side (no exposed keys). MSAL.js auth → app-only Graph auth (no friction for demo, delegated auth as production fix). Pre-sync subset → all files bundleable (zero content limits).

Phase 8: Two Teams

Dev team builds once (Architect, Maker, Communicator, Manager). Ops team runs on query (Researcher, Designer, Maker, Communicator, Manager). Keelin shared as security/QA consultant. 11 agents across 6 role types prove the module's argument that agents are domain-specific, not generic.

Phase 9: UX & Interaction

Three entry points (Guided, Free-text, Browse) converging on one results+refinement panel. Disagreement as first-class interaction: thumbs down (session-level), "Not for this outcome" (catalogue improvement), "Generate something better" (Maker with negative example). Bundle always explicit and deliberate.

Phase 10: Tests Passed

curriculumonline.ie scraping: GO. Gemini Flash vision: GO (10/10 image-heavy PDFs correctly tagged, ~$2 for full parse). DeepSeek text classification: GO (~$3, ~90 min). All blocking unknowns resolved. Ready to build.

Phase 11: Visual Redesign — Warm Library-Card Identity

The initial frontend was functional but stark — white background, standard fonts, minimal styling. The module's UX frameworks (CASA, Fogg B=MAP, Cialdini's liking principle) implied a visual identity should match the system's role: a trusted colleague, not a clinical tool. Claude (via OpenCode) was prompted for a warm, library-inspired theme. Result: Fraunces (serif display) + Public Sans (body) + IBM Plex Mono (mono for badges/confidence scores), cream background (#f2ecd9) with dot-grid texture, library card-catalogue styling for resource cards (top accent bar, double-rule shadow, stacked hover effect), painted-card tab design with polygon clip-paths, and a four-colour semantic badge system. Applied across the frontend, pipeline_thoughts.html, and the QA dashboard. The dot-grid background and warm palette deliberately evoke a teacher's physical resource library — a CASA-aligned visual register that says "trusted colleague" without pretending to be human.

Phase 12: Catalogue Hosting — OneDrive to GitHub Pages JSON

Personal OneDrive (hotmail.com) does not support app-only Microsoft Graph authentication for file operations. The Worker's calls to read Catalogue.xlsx and download resource files returned 401. The fix: serve the catalogue as a static JSON file from GitHub Pages (data/catalogue.json), fetched by the Worker on cold-start and cached in memory. The catalogue_populator.py was redirected to write JSON directly instead of XLSX. This is a practical deployment constraint — documented honestly in Decision 7 and the README Limitations rather than hidden. Consequence: bundle file downloads from OneDrive remain broken for personal accounts (the zip gets README + generated plans but no resource files).

Phase 13: Deep Test Pass — 7 Bugs Fixed, 3 Open Items

Keelin (Dev-Keelin + Ops-Keelin combined) conducted a comprehensive audit against the live deployed Worker and frontend. Seven bugs were found and fixed in a single session: (1) /api/query response stripped catalogue fields (subject, grade_band, format, confidence missing — frontend cards showed no data), (2) duplicate [AI-Generated] badge (system prompt + code both added it), (3) /api/generate-lesson endpoint didn't exist (gap card button returned 404), (4) /api/bundle payload mismatch between frontend and Worker (different field names, missing summary_md), (5) refine/similar query types not handled by Worker, (6) refinement chips toggled visually but never actually filtered results, (7) no loading spinner during searches. Three open items remain: bundle file downloads (OneDrive app-only auth limitation — accepted), catalogue data quality (population in progress), no persistent session state (in-memory only — documented limitation).

Phase 14: Keelin QA Dashboard — 40 Framework Assessments

A comprehensive QA page (qa.html) was built, modelled on the CA2 Emerald Pantry format but mapped to Teacher's Pet's specific domain. The page organises 40 framework assessments across the module's three-pillar structure (Engagement → Intelligence → Partnership), with each framework citing author/year, core claim, and how Teacher's Pet specifically operationalises it. The module's recurring evaluative move — "name the mechanism, don't just assert a conclusion" — is applied throughout. An Assessment Map tab maps every CA3 grading criterion (Agentic Organisation, Handoff & Orchestration, Live Data Gate, Partnership Progression, Governance, AI Disclosure, Trust Calibration) to specific file-and-line evidence. A Functional QA tab documents all 11 findings with live endpoint verification results. The page inherits the warm library-card visual identity for consistency.

Phase 15: UX Restructure — Two-Column Layout with Bundle Sidebar

The single-column results layout was restructured into a two-panel split: a 2-column results grid on the left (60%) and a sticky bundle sidebar on the right (40%). The "+ Add to bundle" button on each card toggles selection state and a "Download Bundle" button in the sidebar triggers the zip download. The header's duplicate Bundle button was removed to avoid confusion. The sidebar uses a warm golden background (#fdf8ec), 2px accent border, and a dividing line under the heading for clear visual separation. Selected cards show a 5px accent left border and tinted background instead of a Unicode checkmark (which was corrupted by encoding issues). Results are sorted by confidence score descending (highest match first).

Phase 16: Select Button Bug — A Hard-Fought Fix

The "+ Add to bundle" button on result cards went through multiple failed approaches: event delegation via handleResultClick, inline onclick attributes, direct addEventListener with IIFE closures, btn.onclick with deferred setTimeout, hidden refinement chip hijacking — none worked reliably. The breakthrough came when it was discovered that calling renderResults() synchronously from within a click handler was destroying the button element mid-event, causing the DOM update to fail silently. The solution: forceRefresh() — a dedicated function that calls renderResults() from a clean call stack. The flow is now: onclick handler toggles state.selectedIds → forceRefresh() → renderResults() rebuilds the DOM with updated state. This approach routes through the same renderResults() path that refinement chips use, which was already confirmed working. The old updateBundleSidebar, updateCardButton, and toggleSelect functions were removed during cleanup.

Phase 17: Guided Dropdowns Fixed, MSAL Popup, Encoding Cleanup

Guided dropdown cascade: The Subject→Strand→Stage→Outcome dropdown chain was broken by three compounding issues: (1) inline onchange attributes referencing non-existent functions, (2) an async race where taxonomies hadn't loaded before the user selected a subject, and (3) Object.keys(lang.strands[val]) returning ["elements"] instead of the actual strand names. Fixed by embedding taxonomy JSON directly as static JavaScript objects (EMBED_LANG/EMBED_MATHS) in the <head>, locking the subject dropdown until data loads, defining standalone handler functions, and correcting the strand key extraction to Object.keys(lang.strands). MSAL popup: Switched from loginRedirect/logoutRedirect to loginPopup/logoutPopup with a normalized redirect URI to prevent browser profile hopping. Encoding: 29 em-dash characters corrupted to U+FFFD during PowerShell file operations, replaced with &#8212; entities then plain hyphens (-). Emoji characters (📚🎯🔍✨📦🗂️) similarly corrupted, replaced with numeric HTML entities (&#128218; etc.).
