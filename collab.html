Case Study: The Bot Behaviour Audit

In early August 2026, Teacher's Pet had been live for three days. The chatbot — a two-stage semantic engine that accepted natural-language queries, searched the 2,895-row catalogue, and returned DeepSeek-ranked results — was returning noticeably patchy results. A teacher asking "Christmas phonics worksheets for Infants" would get phonics worksheets but rarely Christmas ones. A query for "Halloween maths games" returned maths PDFs that mentioned neither Halloween nor games in any satisfying way. The chat concierge, positioned as Teacher's Pet's most advanced feature, was underperforming — and the user asked OpenCode, acting as the full Dev team, to investigate.

What followed was a tightly orchestrated audit across all five agents. It surfaced six concrete bugs, forced two deployment-blocking security interventions, triggered a direct challenge from Architect to Maker over contract compliance, required Manager to cut scope on four unreachable capabilities, and ended with Communicator producing a layered evidence trail that linked every fix to its rubric criterion. This is the story of how that collaboration worked — not as a linear assembly line, but as a series of productive collisions where agents challenged each other and the system got stronger for it.

1. Manager Sequences the Investigation

Dev-Manager opened the session with a rubric-weighted priority stack. "Handoff & Orchestration is 25% of the grade," the build log recorded. "Pipeline reliability is 15%. The chatbot's quality degrades both, because the chat ranking call is part of the orchestration chain. This is not a polish task — this is blocking the highest-weighted criterion."

Manager assigned the sequence: Architect maps the search architecture first (find the structural gaps), Maker audits the code second (find the implementation gaps), Keelin reviews quality third (academic rubric coverage, functional endpoint behaviour, and security — nothing with a high-severity finding gets deployed), and Communicator documents the full chain fourth (every fix needs traceable evidence for the rubric). The build log entry marked the status of all eight rubric criteria and gave the audit a time-box: one session, no scope expansion, "if it's not in the rubric, it's not in sprint."

2. Architect Maps the Search Architecture

Dev-Architect opened the worker.js search path at line 312 — the scoreFreeText() function that powered the first stage of the chat ranking pipeline. What it found was a contract violation: the catalogue schema defined 9 searchable fields (filename, subject, subdomain, format, season, activity_type, grade_band, pedagogy, description), but the scoring function only searched 4. Season, format, activity_type, and grade_band were invisible to keyword matching.

"This isn't a bug," Architect stated, "it's a contract mismatch. The schema was the spec. Maker built against an older version of the spec. The fix is straightforward — add four fields to the search haystack — but the root cause needs documenting because it will recur every time the schema grows." This challenge — Architect holding Maker accountable to the contract, not just accepting whatever was built — is the exact non-linear flow the module's agent design rubric rewards.

Architect then inspected the chat ranking call and found a second structural gap: the DeepSeek API call had no error handling. No !resp.ok check, no choices array validation, no fallback for malformed JSON. A single 500 from DeepSeek would silently produce empty rankings with no warning. "Every data path needs an error branch," Architect noted — quoting its own core belief verbatim.

With Architect's contract audit in hand, Dev-Maker opened the full worker.js codebase and ran a line-by-line inspection. Beyond the two structural gaps Architect had flagged, Maker found four additional implementation bugs:

4. Keelin Blocks Deployment — Twice

Dev-Keelin's review gate is pass/fail for security (always blocks) and severity-gated for academic/functional findings (block only on high severity). Low/medium issues are documented and shipped.

Keelin sign-off: PASS — all 6 bug fixes deployed. Router clean. CORS compliant.

5. Manager Cuts Scope — Four Limitations Accepted

While Maker was fixing bugs and Keelin was running quality review, Dev-Manager was watching the audit's scope. Maker had started proposing additional fixes — "we should build the Ops-Keelin validation gate since we're already in the code," "the UFLI constraint would only take a couple of hours" — and Manager stepped in.

"Not in sprint," Manager recorded in the build log. "Ops-Keelin validation gate is documented in the architecture spec as a future phase. Manager governance functions are specified but not allocated to this sprint. UFLI constraint is listed in the risk register, not the active build plan. These are scope limitations — document them, don't build them."

6. Communicator Documents the Full Chain

With all six bugs fixed, Keelin's quality gate passed, and Manager's scope limitations documented, Dev-Communicator assembled the evidence trail. Communicator produced three deliverables: QA Dashboard entries (all 6 fixes mapped to rubric criteria), Pipeline documentation (Phase 25 — full bot behaviour audit log), and a build log entry (timestamped evidence for AI Acknowledgement).

But Communicator also did something that defines the non-linear collaboration pattern: it challenged two claims that couldn't be verified by running the code. "Maker's commit message says 'plenary always included,' but the pipeline entry implies a 1+ resource minimum. Which is it?" Maker confirmed: plenary is always included now, no minimum. The pipeline entry was corrected. "Architect's contract audit says scoreFreeText searched 5 fields before the fix. The code has 4. Which is it?" Architect confirmed it was 4. The entry was corrected.

Communicator's core belief: "Every claim in the docs must be verifiable by running the code or inspecting the repo." In this audit, that meant two corrections to documentation before the evidence trail was final.

Non-Linear Flows: Agents Challenging Each Other

1. Dev-Keelin Blocks Dev-Maker's Deployment

Before any code reaches production, Keelin runs a three-facet quality review. Security findings always block deployment (secrets, CORS, Graph scopes). Functional findings block on high severity (broken endpoints, silent search failures, bundle drops). Academic findings block on high severity (rubric criterion with zero evidence, agent template violations). Lower-severity academic/functional issues are documented and shipped. Verdicts are PASS or BLOCKED. In the Bot Behaviour Audit, Keelin blocked deployment twice on security findings — once for endpoint exposure, once for CORS misconfiguration. Keelin's gate operationalises Mayer-Davis-Schoorman's (1995) Integrity dimension: "the system having checks."

2. Dev-Architect Challenges Dev-Maker's Implementation

When Maker's implementation deviates from the contract, Architect challenges it with specific line references and contract citations. In the audit, Architect found that scoreFreeText searched only 4 of 9 catalogue fields — "this isn't a bug, it's a contract mismatch." Architect identifies the gap; Maker closes it. This prevents the single most common failure mode in agent pipelines: building the wrong thing because the spec drifted.

3. Dev-Manager Challenges Scope Creep

During a build session, any agent can propose additional work. Manager evaluates every proposal against a single test: does it map to a rubric criterion? If not, Manager blocks it with the standing rule: "If it's not in the rubric, it's not in sprint." In the audit, Manager blocked four proposed expansions — Ops-Keelin gate, governance functions, UFLI constraint, dynamic curriculumonline.ie — and documented them all as accepted scope limitations. This enforces the responsible-innovation framework: "known and explained failures are OK; blind/silent failures are bad."

4. Dev-Communicator Challenges Unverifiable Claims

Communicator's core belief: "Every claim in the docs must be verifiable by running the code or inspecting the repo." In the audit, Communicator found two documentation-code mismatches — Maker's "plenary always included" was ambiguous, and Architect's field count was off by one. Both were corrected before the evidence trail was final. This operationalises the module's trust calibration (Lee & See 2004) at the documentation level.

Key Takeaway: The Non-Linear Shape of Quality

The Bot Behaviour Audit was shaped by four challenge moments — Keelin blocking deployment, Architect correcting Maker's implementation, Manager cutting scope, and Communicator correcting documentation — that interrupted the forward flow and forced the team to stop, verify, and correct. Every one of these interruptions raised the quality of what shipped. The Dev team's architecture produces these collisions as a deliberate design feature, not a workflow accident.

Case Study: From Catalogue to Classroom

A teacher opens Teacher's Pet and types five words into the search bar. What follows is a six-agent pipeline that turns 2,893 catalogue rows into a structured lesson, a teacher-ready resource bundle, and — when something is missing — a freshly generated plan that has already survived a quality gauntlet. This is the story of one real query, told agent by agent.

Ops-Manager STAGE 0 · Orchestration

The Manager classifies the query "Halloween maths for junior infants" as GUIDED MODE — a structured pedagogical request, not a simple catalogue browse. It stamps a runId, opens the audit log, and routes the query to the Researcher. Crucially, the Manager enforces the search-first-then-generate gate: the Maker agent cannot fire before the Researcher has searched the catalogue.

SCOPE LIMITATION The Manager's full governance functions — audit-log analysis, trust-calibration protocol, and the automated disagreement pipeline — are documented but unimplemented in the current codebase.

Ops-Researcher STAGE 1 · Catalogue Search

The Researcher decomposes the query into three facets: season (Halloween), subject (Maths), and grade_band (Infants). It scores every row in the 2,893-entry catalogue across nine fields — filename, subject, subdomain, format, activity_type, season, grade_band, text, and tags — using weighted keyword matching. The design philosophy is precision over recall: a smaller set of high-confidence matches is preferred to a long, noisy list.

The search returns three catalogue matches, each with a confidence score:

ResourceSubjectSeasonGradeConfidence
Halloween_Counting_Cards_01.pdfMathsHalloweenInfants0.92
Spooky_Number_Patterns_JI.pdfMathsHalloweenInfants0.87
Pumpkin_Shape_Sort_Infants.pdfMathsHalloweenInfants0.91

The Researcher also produces a gap report: one outcome the teacher might reasonably expect — a Halloween-themed colour-sorting plenary activity for Junior Infants — has no catalogue entry. The gap is flagged and handed to the Designer.

Ops-Designer STAGE 2 · Lesson Sequencing

The Designer sequences the Researcher's three matches into the three-part lesson structure, adding pedagogical rationale at each stage:

StageResourceRationale
Warm-upHalloween_Counting_Cards (0.92)Low-stakes counting fluency with familiar Halloween objects; activates prior number knowledge with a festive hook.
Main ActivityPumpkin_Shape_Sort (0.91)Hands-on sorting using 2-D shape pumpkins; directly addresses the Shape and Space strand (NCCA 2023).
PlenarySpooky_Number_Patterns (0.87)Collaborative pattern-completion with EAL-friendly visual scaffolds. Confidence caveat applied at 0.87.

Confronted with the Researcher's gap report, the Designer produces a Maker specification: learning objective from the outcome prose, suggested activity type, required materials, differentiation notes (EAL and dyslexia scaffolds), and assessment check.

TENSION POINT Designer refuses out-of-scope materials. If the Designer's pedagogical rationale requires a resource not in the catalogue, the Designer refuses to specify it without flagging the gap. This constraint exists because assuming material availability in Irish primary classrooms is a known failure mode — some schools have full maths kits; others have chalk and a blackboard.
Ops-Maker STAGE 3 · Standalone Generation

Lesson plan generation is a standalone, always-available feature — a dedicated tile in the frontend that the teacher can trigger at any point, on any interaction or bundle, independent of whether catalogue matches were found. The Maker calls the DeepSeek API with the Designer's spec (if a gap was detected and sequenced) or with a general curriculum context, and produces markdown prose only — no worksheets, no images, no printable materials. The generated plan proceeds directly to Ops-Keelin.

Ops-Keelin STAGE 3b · Content QA Gate

Ops-Keelin is the project's quality gate — blunt, pass/fail, line-level. Every generated plan is checked against three criteria:

  • Hallucination check. Are any catalogue filenames referenced that do not exist?
  • Age-appropriateness. Does the activity demand skills beyond the Infants band?
  • Paired-prompt bias testing. Is the plan sufficiently differentiated for EAL and dyslexia learners?
TENSION POINT Keelin blocks a hallucinated reference. Maker Attempt 1 generates a plenary plan referencing Halloween_Colour_Sort_Mat.pdf — a file that does not appear in the Researcher's catalogue output. Keelin flags it: "Hallucination. Reject." Maker regenerates. Attempt 2 passes the hallucination check but introduces the /ch/ digraph, which does not appear until Senior Infants in the UFLI sequence. Keelin rejects again. Two attempts exhausted. The Manager marks the gap as unfilled.

SCOPE LIMITATION The Ops-Keelin validation gate, the UFLI lesson-range constraint, and the paired-prompt bias-testing system are unimplemented in the current code. They are fully documented as accepted scope limitations for the CA3 prototype.

Ops-Communicator STAGE 4 · Output Assembly

The Communicator assembles the final output in two forms: a markdown web summary and a JSZip bundle with README and AI disclosure. AI-generated content is visually distinct. Every resource below 0.85 confidence carries an explicit caveat. Because the gap was marked unfilled, the Communicator includes an honest note: "We identified a gap for a Halloween-themed colour-sorting plenary. Our content-generation system was unable to produce a plan that met our quality standards after two attempts."

How the Ops Team Collaborates

Enforced Pipeline Order

Every teacher query follows the same backbone: Researcher → Designer → (conditional) Maker → Communicator. The Manager sits above this flow, classifying the UX mode on entry, stamping the audit log on every handoff, and blocking any attempt to short-circuit the sequence. The Maker cannot fire before the Researcher has searched the catalogue. This is the search-first-then-generate rule — the most important guardrail in the pipeline.

BDI — Beliefs, Desires, Intentions (Rao & Georgeff 1995)

Each ops agent holds:

  • Beliefs — what the agent knows about the catalogue, the query, the teacher's class level, and the state of the pipeline.
  • Desires — the goal state. For the Researcher, high-precision matches; for the Designer, a pedagogically sound sequence; for Keelin, a plan that survives all three checks.
  • Intentions — the concrete action: scoring rows, producing a three-stage lesson, rejecting a hallucinated file reference.

PEAS Agent Specification (Russell & Norvig 2021)

PPerformancePrecision of catalogue matches; gap-detection accuracy; quality of generated plans (hallucination-free, age-appropriate, differentiated).
EEnvironmentThe 2,893-row resource catalogue; the DeepSeek API; the teacher's query string and class-level context; the audit log.
AActuatorsMatch lists and confidence scores; lesson sequences and Maker specs; generated markdown; pass/reject decisions; JSZip bundles; audit-log entries and routing decisions.
SSensorsThe query string and UX mode classification; the catalogue; the match list; the gap report; Maker output; Keelin's validation results.

Trust Calibration (Lee & See 2004 / Mayer-Davis-Schoorman 1995)

  • Ability — Does the Researcher find what the teacher needs? Measured by match precision and gap-report accuracy.
  • Benevolence — Does the system act in the teacher's interest? The Keelin gate exists solely to prevent low-quality content from reaching a classroom.
  • Integrity — Does the system tell the truth about what it can and cannot do? The honest gap-reporting, AI disclosure, and documented scope limitations all signal integrity.

Non-Linear Flows: Where Agents Push Back

1

Designer Refuses to Use Materials Outside the Catalogue

BLOCKS PIPELINE

When the pedagogical rationale calls for a resource not in the Researcher's match list, the Designer refuses to silently assume its availability. Instead, it flags the gap and produces a Maker specification. This exists because assuming material availability in Irish primary classrooms is a known failure mode.

2

Ops-Keelin Blocks a Hallucinated File Reference

REJECT · ATTEMPT 1

Maker references a file not in the catalogue. Keelin cross-references the Researcher's match list, finds no such file, and rejects with a line-level citation. In a classroom context, a teacher following a plan referencing a non-existent resource loses planning time and trust.

3

Ops-Keelin Catches a UFLI Sound-Boundary Violation

REJECT · ATTEMPT 2

Maker's second attempt passes the hallucination check but introduces a sound beyond the class's UFLI lesson range. Keelin checks the scope-and-sequence, finds the violation, and rejects. Introducing sounds before they are taught is a known failure mode in LLM-generated literacy content.

4

Manager Detects a Researcher-Designer Disagreement

LOGGED, NOT SILENCED

The Researcher returns a match at confidence 0.92. The Designer flags it as pedagogically unsuitable — the activity type is "worksheet" but worksheets are inappropriate as a warm-up for Junior Infants. Rather than suppress the conflict, the Manager logs it with both agents' rationales and surfaces it via the Communicator.

5

Manager Enforces Search-First-Then-Generate

HARD GATE

The Maker is the most resource-intensive and risk-prone agent. The Manager enforces that it never runs before the Researcher has completed its catalogue search. If the Researcher returns zero matches, the pipeline skips directly to the Communicator — a hallucinated lesson plan is worse than no plan.

6

Two Strikes and the Gap Is Unfilled

TERMINAL

After two rejections, the gap is marked unfilled and the Manager instructs the Communicator to present it honestly. This is a deliberate quality-over-coverage trade-off: the platform would rather admit a gap than pump a low-quality plan into a classroom. The limit also prevents an infinite correction loop burning API credits.

Partnership Progression Ladder

The Partnership Progression ladder (del Rosal 2024, HUMANLIKE) maps the evolution of human-AI collaboration across four rungs: Tool → Advisor → Digital Colleague → Partner. Each rung reflects an increasing level of agency, initiative, and trust.

AgentLadder RungJustification
Ops-Researcher ADVISOR Scores matches, produces confidence ratings, identifies gaps — adding a layer of judgment beyond raw search. Does not initiate action or challenge other agents; produces a structured artefact and hands it downstream.
Ops-Designer DIGITAL COLLEAGUE Sequences resources with pedagogical rationale, refuses to design beyond catalogue constraints. This refusal is an independent boundary-setting action — it exercises bounded autonomy within a defined domain.
Ops-Maker TOOL Generates only when explicitly triggered, only from a Designer-provided spec, only in markdown prose. No independent judgment. A deliberate constraint on the riskiest component.
Ops-Keelin DIGITAL COLLEAGUE Exercises the highest bounded autonomy: binary pass/fail decisions that alter pipeline output, enforces quality standards independently, terminates the generation loop after two failures. Has the authority to say "no" with line-level evidence.
Ops-Communicator ADVISOR Assembles and caveats output but does not independently alter lesson structure or resource selection. Advises through confidence caveats and gap disclosures; leaves final judgment to the teacher.
Ops-Manager DIGITAL COLLEAGUE Classifies UX mode, enforces pipeline gates, logs disagreements, makes routing decisions no other agent can override. Its architectural role — an orchestrator with enforcement authority — places it firmly in the Digital Colleague rung.

NOTE No agent in the current pipeline reaches the Partner rung. A Partner-level agent would proactively identify a teacher's unstated needs, adapt its behaviour based on longitudinal data, and co-create resources with the teacher in a sustained collaborative relationship. This is the long-term aspiration of the Teacher's Pet project but lies beyond the CA3 prototype scope.
