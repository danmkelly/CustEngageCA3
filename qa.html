Week 6–7 — CASA, Conversation Flow, Grice, Service Blueprinting

Design note: Teacher's Pet is not a chatbot

Teacher's Pet is a search concierge with a static web UI — not a conversational agent. CASA (Computers Are Social Actors), conversation flow anatomy, and chatbot-specific frameworks apply differently than they would to a chatbot. This is not a gap — it's a deliberate domain choice. The assessment below maps where the frameworks' principles are honoured through alternative mechanisms (visual design, progressive disclosure, error recovery) rather than through conversation turns.

IDFrameworkAuthor(s)AssessmentStatus
I01 CASA — Computers Are Social Actors Reeves & Nass (1996) Despite not being a chatbot, Teacher's Pet honours CASA principles: (1) Turn-1 disclosure: the UI header says "Catalogued. Matched. Ready by Monday" — establishes identity as a concierge, not a person. (2) No fake-human cues: no avatar, no simulated typing, no conversational persona. (3) Register matches capability: warm professional tone (library card aesthetic) without over-promising. (4) Frustration handling: error banners with auto-dismiss (15s), exclusion section for rejected resources, "No resources found" gap cards with actionable alternatives. The module's bright line — "disclose bot status in turn 1" — is satisfied by the visual identity: the AI badge on generated plans, the confidence scores, and the bundle disclosure. PASS

Intent: guided (curriculum outcome), freetext (resource recall) — two distinct intents, each with its own form. Slots: guided mode uses progressive dropdowns (one selection at a time, validated); Interactive Bot Selection takes a natural-language query with conversation history. Recovery: gap cards with actionable alternatives ("Search curriculumonline.ie" + "Generate lesson plan"); error banners; excluded section for rejected resources. Closer: bundle download with summary README and AI disclosure. The module's core ethic — "design the unexpected first" — is satisfied: the system handles zero results (gap cards), API failures (error banners), and user disagreement (thumbs down + exclusion). Quantity: results capped at 20; descriptions truncated to 140 chars (expandable); gap cards concise. The module's diagnostic frame: "why does this reply feel wrong? → which maxim broke?" applies here to the UX — "why does this search feel off?" maps to Manner (confusing UI), Quantity (too many/few results), or Quality (bad matches). PASS
I04 Service Blueprinting Bitner, Ostrom & Morgan (2008) Line of interaction: teacher ↔ search UI (two modes, refinement bar, result cards, bundle button). Each result click, each chip toggle, each bundle — a moment of truth. Line of visibility: above the line: the frontend. Internal line: DeepSeek API (generation), curriculumonline.ie (scraping), GitHub Pages (catalogue JSON). The blueprint reveals a critical failure point: the bundle can't download files from personal OneDrive (app-only auth limitation — the backstage process silently fails while the frontend shows "Preparing your bundle"). This is exactly the kind of failure the module's blueprinting is designed to reveal — the README lists download errors, but the teacher sees a zip download succeed (with only README + generated plans inside). I05 Uncanny Valley Mori (1970/2012) Teacher's Pet sits deliberately on the "clearly AI" side of the valley. No attempt at human impersonation. The [AI-Generated] badge, confidence scores, and library-card aesthetic signal "this is a tool for teachers, by a teacher (with AI assistance)" — not "this is a replacement teacher." I09 Partnership Progression Ladder del Rosal (2024), HUMANLIKE Tool: the system answers searches and stops (freetext/chat — gives you results, you decide). Advisor: guided mode recommends resource sequences with confidence scores; gap reports suggest alternatives. Digital Colleague: the Ops pipeline owns the end-to-end resource matching + sequencing + gap detection workflow — bounded lane, escalates gaps to the teacher. Partner: not claimed. The system does not have memory, judgment, or standing across sessions. The module warns: "name it, don't overclaim it." Teacher's Pet operates at Tool↔Advisor↔Digital Colleague, depending on the mode — and is honest about it. PASS

Reflection: Known and Explained LLM Weaknesses

The module frames the CLARA moment as "what changes across the arc is the kind of work the system is trusted with" — and the evidence that earns that trust should get harder to satisfy, not softer. This audit reveals four documented weaknesses where the system falls short of its own agent specifications. These are not bugs — they are scope decisions where implementing the full spec would require embedding-model search, multi-step LLM validation pipelines, and curriculum taxonomy parsing that exceeds CA3 constraints. They are documented here honestly, per the module's requirement that "known and explained failures are OK; blind/silent failures are bad."

1. Ops-Keelin Validation Gate — Unimplemented

Spec says: Ops-Keelin validates every Maker-generated lesson plan for hallucination detection (verifying catalogue filename references), UFLI sound boundary checks (no graphemes beyond the class's lesson range), age-appropriateness of vocabulary, and paired-prompt bias testing for EAL/dyslexia tags. Plans that fail validation are returned to Maker (max 2 attempts); after 2 failures, the gap is left honestly unfilled.
Reality: Zero implementation. Generated content flows directly from Maker to Communicator with no validation gate whatsoever. The pipeline structure (Researcher → Designer → Maker → Communicator) is architecturally correct — Keelin was designed as a gate between Maker and Communicator — but the gate itself was never built.
Why it matters: Without Ops-Keelin, every generated lesson plan reaches the teacher unverified. A plan could reference non-existent catalogue files (hallucination), introduce sounds ahead of the UFLI scope (developmental inappropriateness), or fail to differentiate for EAL learners — and no one would know.
Why documented, not fixed: Implementing Keelin requires: (1) a second DeepSeek call per generated plan to verify filename references against the catalogue, (2) UFLI grapheme extraction from generated prose via regex or LLM, (3) a paired-prompt re-generation pipeline that doubles API costs, and (4) a pass/fail feedback loop with retry logic. This is a full agent in its own right — ~3-4 hours of implementation with 2-3x the per-query API cost. It is the single most impactful missing piece and the first feature to build in the next iteration.

2. Manager Governance Functions — Missing

Spec says: The Manager should write a complete audit log row per session (including excluded resources, disagreement records, Keelin QA outcomes, and bundle delivery confirmation), then periodically read the audit sheet and produce a governance report covering: total sessions, mode distribution, average match confidence, top uncovered outcomes, disagreement frequency, generation rate, and recommended catalogue maintenance actions.
Reality: The audit log is written (fire-and-forget, non-blocking) but contains only 9 of the spec's 13 fields — missing: resources excluded with rationale, disagreements flagged (which agents, what about, resolution), Ops-Keelin QA outcome (pass/fail with feedback), and bundle delivered flag. There is no endpoint or function that reads the audit sheet and produces a governance report.
Why documented, not fixed: The audit log infrastructure works (MS Graph table-rows endpoint, app-only auth). Completing it requires adding the missing fields to the logToAuditSheet call and implementing a read→analyse→report pipeline — a significant engineering task. The log is written, which satisfies the "some audit trail exists" bar; the analysis layer is the gap.

3. UFLI Lesson-Range Constraint — Missing

Spec says: The Researcher must enforce UFLI lesson scope as a hard boundary — never suggest a resource containing graphemes or irregular words from lessons beyond the class's current range. The Maker must include the UFLI lesson range in its DeepSeek prompt and scan generated prose post-generation for boundary violations.
Reality: No UFLI lesson-range parameter is consumed or enforced anywhere in the pipeline. The taxonomy (128-lesson scope-and-sequence in taxonomy/ufli.json) exists and is loaded, but no agent references it. Generated plans may introduce untaught sounds, and catalogue matches for UFLI queries are keyword-only (matching filename or programme_ref string), not scope-constrained.
Why documented, not fixed: The data exists — the 128-lesson scope-and-sequence maps each lesson to specific grapheme-phoneme correspondences and irregular words. Implementing the constraint requires: (1) a UFLI lesson-range parameter in guided/freetext modes, (2) a JSON lookup that returns the ceiling of allowed sounds for a given lesson number, (3) regex-based sound detection in generated prose to scan for violations. This is specification-rich but implementation-heavy — a ~2-hour task with meaningful complexity.

4. curriculumonline.ie Fallback — Single Hardcoded URL

Spec says: When gaps are identified, construct a curriculumonline.ie search query from the outcome prose, fetch relevant page titles and URLs, and return them tagged as external/supplementary — never blended with catalogue results.
Reality: The fallback always scrapes the same hardcoded Reading strand URL regardless of what outcome the teacher queried. A gap in the Maths curriculum triggers a Reading strand scrape — completely wrong context. Discovered items are labeled with source="curriculumonline.ie" but contain only code+prose, not actual page titles and clickable URLs.
Why documented, not fixed: curriculumonline.ie has no public search API — it is server-side rendered HTML. Constructing dynamic search URLs would require reverse-engineering their query parameter structure and parsing arbitrary search result pages, which is brittle and unreliable. The current implementation demonstrates the fallback concept (the architecture is correct: scrape → discover → suggest) but the scraping target is static. A production fix would use a proper search API or pre-indexed curriculum resource links.
