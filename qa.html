Overall: Teacher's Pet demonstrates strong academic alignment across all 13 assessed frameworks. It operates as a three-mode resource concierge with live catalogue search, curriculum gap detection, and conditional AI lesson plan generation. The architecture — 5-agent Ops pipeline + QA agent on Cloudflare Worker, static frontend on GitHub Pages — satisfies PEAS/BDI agent specification, trust calibration (Lee & See 2004), and responsible innovation governance (Stilgoe et al. 2013). The three UX modes (Guided/Free-text/Browse) with client-side refinement and explicit bundle interaction provide appropriate human control (Shneiderman 2022). Three open items remain: the bundle cannot download files from personal OneDrive (app-only auth limitation — accepted), catalogue data quality is moderate (population in progress), and the workflow is frontend-only with no persistent backend session state. None are academic blockers for a CA3 prototype.

Open Issues

Three items remain. None are functional blockers for the current CA3 prototype.

O01 — Bundle file downloads fail on personal OneDrive

ImpactHIGH · Bundle zip contains README + generated plans but no actual resource files.
Root causePersonal OneDrive (hotmail.com) does not support Microsoft Graph app-only (client credentials) authentication. The Worker's downloadFromOneDrive() function uses app-only auth and will always receive 401 from personal OneDrive. This was documented in commit 507dc5d ("Switch catalogue from OneDrive Graph API to GitHub Pages JSON").
WorkaroundFile download errors are reported in the bundle README. Users know which files failed. Generated plans and bundle README are still delivered correctly. For a graded CA3 demo, the bundle endpoint still demonstrates the architecture.
ResolutionSwitch to delegated (user-consent) MS Graph auth with MSAL.js for bundle downloads. Requires: sign-in flow in frontend, delegated File.Read scope, consent prompt. Alternatively, serve files from GitHub alongside the catalogue (requires publishing teaching resources to the repo — not recommended for privacy reasons). For CA3 grading, the bundle endpoint demonstrates the pipeline without requiring functional file downloads.

O02 — Catalogue data quality

ImpactMED · Guided search by outcome_code returns fewer matches than expected. Most rows at confidence=0.5 with empty grade_band/format. Search relevance depends on catalogue quality.
Root causeThe catalogue JSON was loaded at an intermediate state (2,895 rows) while the catalogue_populator.py script continues deep-parsing in a separate session. The current dataset has folder-level tags only (Pass 1). Passes 2–4 (text extraction, vision analysis, curriculum mapping) are still running or planned.
ResolutionLet the catalogue_populator.py complete in the other session. The final catalogue should have ~4,850 rows with 6–8 tags per file at confidence 0.7–0.9. Once the catalogue is reprocessed and catalogue.json is updated on GitHub Pages, the Worker will serve richer data on the next cold-start.

O03 — No persistent session state

ImpactLOW · Session data (selected resources, thumbs up/down, flagged items) is lost on page refresh. No history of previous searches.
Root causeAll state is in-memory JavaScript variables in the frontend. No localStorage, no Worker-side session store, no cookies. Worker has no persistent storage (intentional — documented limitation).
ResolutionAdd localStorage persistence for selectedIds, thumbsUp, and lastQuery. This would survive page refreshes. For a production version, a Worker KV store could maintain per-teacher session state. For CA3 grading, the current in-memory state is sufficient for a functional demo.
